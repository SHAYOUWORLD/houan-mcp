# ADR 0004 — NDL Kokkai API への問い合わせを直列化し、3秒以上あける

- Status: Accepted
- Date: 2026-10-28
- Related: ADR 0002

## Context

NDL 国会会議録検索システム API の案内（<https://kokkai.ndl.go.jp/api.html> の「4. 利用条件・免責事項」。2026-10-28 確認、ページの最終更新は 2026-06-29）は、機械的なアクセスに次の2点を求めている。

- 多重リクエストを避ける
- データを取得し終えてから数秒程度あけて、次のリクエストを送る

v0.1.3 までの実装は、どちらも満たしていなかった。

- 待ち時間がない。続けて届いた `tools/call` は、前の応答を読み終えた直後に NDL へ送っていた（fetch を差し替えたテストで 3〜4ms 後）。
- 同時件数の上限は、全オリジン共通の 4 件（v0.1.1 で入れた `RATE_LIMIT_MAX_INFLIGHT`）だけだった。stdin の行は1行ずつ処理するが、JSON-RPC のバッチ（配列）は `Promise.all` で並行に処理するため、NDL へ最大 4 件を同時に送れた。

## Decision

- NDL（`https://kokkai.ndl.go.jp`）への fetch を、プロセス内の1本の Promise チェーンに並べて直列化する（同時1件）。
- 各リクエストは、前のリクエストが終わった時点（本文の読み込み完了。失敗・タイムアウトも含む）から 3000ms 以上あけて送る。
- 環境変数 `HOUAN_MCP_NDL_INTERVAL_MS` で間隔を延ばせる。3000 未満の値は無視し、利用条件を下回る設定はできないようにする。
- 5分キャッシュに当たった問い合わせは NDL へ送らないので、待たない。
- タイムアウト（`HOUAN_MCP_TIMEOUT_MS`）は送信時から数え、順番待ちの時間は含めない。
- 衆議院・参議院の議案ページは NDL の順番待ちに巻き込まない（従来どおり、全オリジン合計で同時4件まで）。
- `test/ndl-pacing.test.mjs` で、fetch だけを差し替えた実際のサーバープロセスに対し、NDL への同時件数が常に1件であること、前の完了から次の開始まで 3000ms 以上あくこと、環境変数の下限と延長が効くことを確かめる。

3000ms は、案内の「数秒程度」を下限側で読んだ値。

## Consequences

### 良い点

- NDL の利用条件（多重リクエストの回避と数秒の間隔）を、コードとテストで保証できる。
- 案内が変わっても、定数1つとテストの期待値を変えれば追随できる。

### 悪い点

- NDL へ続けて問い合わせると、2件目以降は1件ごとに約3秒待つ。`find_diet_qa` を5回続けて呼ぶと、待ちだけで12秒以上かかる。
- 直列化はプロセス単位。複数のクライアントがそれぞれサーバーを起動した場合の合計は制御できない（README に明記）。

## Alternatives Considered

### 200ms 程度の短い待ち

連続取得の負荷は下がるが、「数秒程度」を満たさない。却下。

### 環境変数で 0 まで下げられるようにする

利用条件を下回る設定を配布物が許すことになる。テストは fetch の差し替えで回せるので、下げる手段は用意しない。

### 衆参の議案ページにも同じ間隔をかける

今回は NDL の利用条件への対応に絞った。衆参側の間隔は別途判断する。
